## 二、四大展示模块

### 2.1 项目设计（0:00–18:00）

**目标一句话：让外行评委在 6 分钟内看懂「真实问题—作品价值—三个机制」，再用 12 分钟讲清选题思路、内容结构、技术取舍和四人分工。**

#### 口播稿（可直接照读）

**【0:00–1:00 开场】**

（A 走到主讲点，站定 2 秒，扫视评委，微笑）

「各位评委老师好，我们是××学校参赛队，中职组新一代信息技术赛道。我们的作品叫《反诈剧本杀》。一句话：**把真实诈骗案做成一本可以走进去的书**——学生每点一步，损失金额就涨一次；结束后逐节点告诉他错在哪一步，而且每个节点都能翻回公开报道原文。今天 60 分钟，我们按四个模块讲：项目设计、现场工作流程、我们掌握的核心技能、可核验的主要成果。」

**【1:00–3:30 真实问题：一个高中生，两个多月，5 万余元】**

（D 切 PPT 第 2 页；A 用手掌指向案件时间线，不遮挡文字）

「先看一个真实案件。2025 年 8 月 22 日，人民网四川频道转载华西都市报报道：四川内江一名高中生王同学，在二手平台看到一个 5000 元的游戏全皮账号，先付 300 元定金，又按对方要求扫码付了 4700 元尾款；接着对方说电话卡里有 1400 元话费，让他『还』回去；再以『银行卡流水不够、刷够才退款』为由，让他陆续转账 4 万多元；最后账号没拿到，人被拉黑，两个多月一共被骗 5 万余元。**他不是不知道有诈骗，而是每一步都觉得『钱都付了，再给一次就能拿回账号』。**」

**【3:30–6:00 现有教育缺哪一环 + 我们的三个机制】**

（D 切 PPT 第 3 页，停 2 秒，再切第 5 页）

「现有反诈教育大概三种：宣传片，看完就忘；题库答题，知道不等于会做；新闻案例，离自己太远。它们缺同一个闭环：**做一次选择 → 看见后果 → 有人告诉你为什么错 → 你能自己再走一遍正确的路。** 我们的作品补的就是这个闭环。」

（B 把手机举起 5 秒，屏幕朝评委，停在书架，不点；然后收回支架）

「三个机制：第一，**损失账本**，每选一步，钱实时减少；第二，**逐节点复盘**，不是给一个分数，而是逐条告诉你第几步、选了什么、风险、为什么错、正确做法；第三，**每个节点可溯源**，话术和金额都能翻回公开发布的原报道。这些不是买来的模板：**32 个 Java 类、4,532 行代码，17 本剧本、405 个节点、71 条来源，全部在我们自己的仓库里**；后面会给评委看提交记录、版本和实机截图。如果今天只记一句话：**我们不是不让学生点错，而是让他在 App 里先安全地错一次，并且知道错在哪一步、值多少钱。**」

（C 在 6′ 举牌；A 看到后点头，进入下一段）

**【6:00–10:30 选题思路：为什么反诈、为什么中职生、为什么是「书」】**

「为什么是反诈？我们学校在中职，15–16 岁的学生有手机、玩网游、会买卖账号，但社会经验少；电信网络诈骗是真实发生在同龄人身上的事。我们调研时先列了 6 类高发骗局：**游戏账号、刷单返利、冒充客服、冒充公检法、校园贷兼职、AI 换脸**。」

「形态上我们对比了三种现有做法：宣传片是『看』，题库是『记』，新闻是『读』。它们都没有让学生自己做一个会承担后果的决定。所以最后选了『书架 + 一本书』：点开书 → 翻页 → 进入聊天 → 每一步做选择 → 结束时复盘。**书是一个低门槛的入口，也是一个可以不断加册的内容容器。**」

**【10:30–14:00 内容结构：6 类、17 本、405 个节点、71 条来源】**

（C 递内容规模卡；D 切 PPT 第 8 页）

「现在有 **6 类、17 本剧本、405 个剧情节点、71 条可核验来源**。每本书对应一类骗局；每本剧本 21–30 个节点、12–18 步通关、3–6 个结局；单局按剧本卡标注 6–15 分钟。这些数字不是背的，是脚本校验出来的：`py tools/validate_script.py` 现在 17 本全部通过、0 错误。」

「内容不是编的。流程是：公开报道 → 提取话术和金额 → 改编成节点（人物匿名、平台名虚构）→ 跑校验脚本查格式 → 人工逐条对原文 → 进版本。所有来源在 `docs/sources.md` 和每个剧本的 `sources` 字段里。**评委随便抽一个节点问依据，我们都能翻回公开报道。**」

**【14:00–18:00 技术取舍与分工：把技术做轻，把内容做真】**

（D 打开 `artifacts/技术路线图.png`；A 指四层架构，从左到右）

「技术上我们刻意做轻：**Android 原生 Java，零第三方依赖，零权限，零联网，安装包 2.55 MB**。为什么？第一，评委可以现场翻代码；第二，学校机房和学生的旧手机都能装；第三，不采集任何学生信息，学校敢推。剧本是数据不是代码：17 个 JSON 放在 `assets` 里，**加一个文件就多一个剧本，不改一行 Java**。界面用 XML + Canvas 手绘，没有第三方图片素材。」

「工程上四层：model / engine / ui / assets。四人分工：内容与来源、实现与测试、材料、答辩；每天提交，演示前 3 天冻结，只修崩溃。AI 我们用了，但只用于提效：**不让 AI 生成案例事实、来源、金额和测试数据**；每条来源人点开原文核对，每个数字人能追到出处，代码编译通过、真机走通才进版本。」

（18′ 举牌；A 转向手机，进入工作流程）

### 2.3 核心技能（42:00–52:00）

**目标一句话：用四个可复现的技术动作证明——书架、翻书、聊天、账本、复盘、工坊、海报、小组件都是学生自己写出来的，不是网页套壳，也不是拼图。**

#### 口播稿（可直接照读）

**【42:00–44:30 技能①：剧本是数据，不是代码】**

（D 把电脑切到 `app/src/main/assets/scripts/game-account.json` 前 40 行；终端/截图显示校验结果）

「第一个动作是**数据建模**：剧本不是写死在 Java 里，而是一份 JSON。每个节点有 id、说话人、第几幕、台词、2–3 个选项；每个选项有 next、risk、tag、cost、feedback。**加一本剧本只要加一个 JSON 文件**，书架、剧本页、复盘页、来源页全部自动生效——这是我们敢在短周期里做出 17 本内容的原因。」

「格式靠脚本兜底：`tools/validate_script.py` 检查 JSON 语法、next 是否存在、非结局节点是否至少 2 个选项、结局节点是否没有选项、节点是否可达、金额大于 0 是否标高风险、来源字段是否齐全。**现在 17 本全部通过、0 错误。** 评委可以现场抽一个剧本，我们打开 JSON 给您看。」

**【44:30–46:30 技能②：Canvas 手绘 + 动画时间轴】**

（D 打开 `PixelBookView.java` 的绘制段和 `ChatActivity.java` 的 `renderNode()` 时间参数）

「第二个动作是**图形与动画**：书架上的书、翻页、头像、分享海报，全部用 Canvas 画，没有第三方图片素材。翻书是四段动画：**420 毫秒移到屏幕中央、560 毫秒封面沿书脊掀开、320 毫秒内页淡入、620 毫秒停留**；聊天消息间隔 660 毫秒，系统消息 420 毫秒；损失数字滚动 420 毫秒。我们调这些时间，是为了让手机上的体验像真的聊天，而不是像答题。」

「还有一个细节：同一个骗子换号时，说话人的名字和头像颜色会跟着换——**换号、换名、换色**，这是真实骗局里的高危信号，也是我们在 14 个剧本、65 个节点里同步改过的。风险颜色只在复盘出现，玩的时候不剧透——这是设计，也是代码里写死的规则。**学生能讲清楚每一个时间参数为什么是这个值。**」

**【46:30–49:00 技能③：零权限不等于功能少】**

（D 打开 `AndroidManifest.xml`，指「零权限」注释和没有 uses-permission 的区域；B 指手机状态栏飞行模式）

「第三个动作是**用系统能力替代权限**。导入导出走系统文件选择器（SAF）；分享海报走自建 ContentProvider，只授权单次读取；桌面小组件走 AppWidget；所有数据只存本机 SharedPreferences。**Manifest 里没有一条 uses-permission，构建里没有一条第三方依赖，代码里没有网络请求。** 零权限不是功能少，是刻意设计：不收集学生信息，学校才敢推。」

**【49:00–52:00 技能④：质量闭环】**

（B 在 App 里：设置 → 长按「关于」2 秒 → 运行日志页；D 打开 `git log` 和 commit `29194e8`）

「第四个动作是**质量闭环**。运行日志藏在设置里，长按『关于』2 秒打开，只写本机、可复制；它记录页面跳转、每次选择、金额变化、导入导出、引导过程和崩溃堆栈。我们靠它定位问题、修问题。」

「比如『新手引导卡死』这个真实 bug，我们做了三重保险：点遮罩也能继续、固定位置永远能点的『跳过引导』、1.6 秒内某一步显示不出来就自动结束。再比如超大字号顶栏溢出，我们让标题和金额自动降档、给账本留最小宽度，1.55 倍『超大』也不会撞在一起。**10 项缺陷是一次提交修的，代码里能看到修复前后的逻辑。** 配合 123 张实机截图、31 次提交和 4 个 Release，这些不是 PPT 上的故事，是仓库里的记录。」

## 四、素养与礼仪（贯穿评分）

### 4.1 站位

```
                       投影幕（16:9）
        ┌──────────────────────────────────────┐
        │                                      │
        └──────────────────────────────────────┘

  A 主讲（屏幕左前 1.2–1.5m，面向评委 30–45°）
                                  B 操作（演示台右侧，手机支架）
        D 补位（后右半步，Q&A 上前）
                                  C 材料/计时（右侧幕边/侧桌，A 余光可见）

        ───────────────  评委席  ───────────────
```

- **A 主讲**：站在屏幕左前方，距屏幕 1.2–1.5 米；身体与屏幕成 30–45°，不要正对屏幕背对评委；指屏幕时侧身，不挡住投影。
- **B 操作**：站演示台右侧，手机平放/支架，身体不前倾挡屏；与 A 保持约 1 米；不站在 A 与评委之间。
- **C 材料/计时**：右侧幕边或侧桌，A 余光能看到；材料按顺序摊开，不现场翻箱。
- **D 答辩补位**：后场电脑桌靠右；Q&A 时走到 A 右后方半步，答完退回；不抢话。
- **赛前踩点**：用胶带标 A/B/C 三个点；走一遍上台路线；确认插座、投屏距离、评委席视线。

### 4.2 手势

- 指屏幕：**五指并拢、掌心向上**，手臂自然伸直，指向内容后停 1 秒再说话；不单指戳屏幕、不遮住文字。
- 说「请看」：手掌摊开朝向屏幕，不甩手、不画圈。
- 说数字：手掌摊开向上，像「把数字交给评委」；不掰手指逐个数。
- 递材料：双手托底，正面朝评委；等对方接稳再松手；不越过 A 递。
- 递手机：双手托底，屏幕朝向评委；评委拿稳再松手；不递到设置页/分享面板。
- 不做：抱臂、插兜、背手、摸头、转笔、抖腿、频繁看表、抠手指、扶眼镜超过 2 秒。
- 眼神：每 20–30 秒扫评委席左/中/右；说数字看评委，不盯屏幕；评委提问时身体转向提问者，答完转回。

### 4.3 避免口头禅清单

| 口头禅 | 替换说法 |
|---|---|
| 然后……然后…… | 停 1 秒，或说「接下来」 |
| 就是说 / 也就是说 | 直接说结论 |
| 那个 / 这个这个 | 停 1 秒，想好再说 |
| 其实 | 删掉 |
| 对不对 / 是不是 | 「请评委看屏幕」 |
| 大概 / 差不多 / 应该是 | 数字必须精确；不确定就说【待实测】 |
| 反正 | 删掉 |
| 大家可以看到 | 「请看屏幕左上角/这张卡」 |
| 嗯 / 呃 / 啊 | 停 1 秒，不拖音 |
| 我再说一遍 | 「关键数字再重复一次」 |
| 简单说 | 直接说 |
| 非常非常 | 「很」 |
| 所以说 | 「因此」 |

> 彩排时录音，每 10 分钟数一次；目标全场 ≤6 次。超过就重录那一段。

### 4.4 语速、停顿、声音

- 语速：每分钟 220–240 字；开场和收尾放慢到 200 字。
- 停顿：每个关键数字前后各停 1 秒（300、4,700、1,400、34,400、50,400、6/17/405/71）。
- 句子：每句 ≤25 字；一段 ≤4 句；短句比长句稳。
- 声音：比平时大 20%，用腹式呼吸；不喊；麦克风距离 5–10 厘米，不吹气、不拍话筒。
- 眼睛：说结论看评委，指屏幕时眼神跟着手指，指完回评委。
- 不喝水时说话；水杯放桌下，瓶盖提前拧松。

| 时点 | C 的动作 | A 的回应 |
|---|---|---|
| 6′ / 18′ / 42′ / 52′ | 举黄色数字牌（6/18/42/52），举 3 秒 | 点头，按总表进入下一段 |
| 55′ | 举白牌「5」 | 开始收尾当前模块 |

> 手势只给 A 看，不给评委看；C 不喊、不敲桌、不走到台前。

### 4.6 答辩礼仪

- 评委提问：停下当前动作 → 身体转向提问者 → 听完 → 点头 → 「谢谢老师，我先给结论」→ 结论 → 证据 → 边界。
- 回答 ≤40 秒；不抢话、不打断评委；不会就说不会，不编。
- 评委要求操作：B 递手机/切页面，A 说明；不要两个人同时说话。
- 评委质疑：先接住（「您这个担心是对的」），再给证据，最后说边界；不辩解、不反问评委。
- 评委示意停：立即停，感谢，问「需要我们把演示机送过去吗」；不继续讲。
- 结束：感谢，后退半步，等评委示意再转身；不立刻收拾东西。

## 五、兜底方案

### 5.1 总原则：3 秒判断、10 秒切换、5 秒内解释不超过一句

1. 不在台上修手机、不重启电脑、不现场重装、不清数据。
2. 主讲永远有话说：切视频后照常讲，不冷场。
3. 任何数据说不清，就说「这个数还没测，标了【待实测】」，不临时编。
4. 故障解释不超过一句；不道歉超过一次；不把责任推给设备/队友。
5. 先保「真实问题、错误路线复盘、来源、待实测口径、声明」；可砍工坊、中途止损、技能细节。

## 七、评委追问应答（12 题）

> 统一结构：**先结论（1 句）→ 再证据（1–2 个具体文件/页面/数字）→ 最后边界（哪里还没做到）**。每题 ≤40 秒；不会就说「这个还没做/没测，材料里标了【待实测】」，不编。

**Q1：你们和反诈宣传片、班会课、题库 App 有什么区别？**（A 答）

「区别在『决策 + 复盘』。宣传片是看，题库是记，新闻是读；我们的作品让学生自己做 13 次选择，每次选择立刻变成损失金额；结束后逐节点告诉他第几步、选了什么、为什么错、正确做法。我们补的是反诈教育里最缺的复盘这一环。」

**Q2：案例是真的吗？来源可靠吗？你们和公安有合作吗？**（A 答；C 递来源卡）

「案例来自公开报道，能打开原文：人民网四川频道 2025-08-22《为买游戏账号高中生被骗5万多元》；合肥网 2025-07-09《买卖网络游戏账号和装备类诈骗》，转载并标注来源公安部刑侦局。300、4700、1400 与原文一致；『4 万多元刷流水』原文没有逐笔金额，剧本拆成 8000 和 20000 两笔，这一点我们在来源页和答辩里都说明。**我们没有与公安或反诈中心合作，也没有官方认证**；作品是教学演示、案例据公开报道改编。」

**Q3：零权限、零联网，怎么证明？会不会是口号？**（D 答；可开 Manifest）

「三层证明。代码层：`AndroidManifest.xml` 里没有一条 `uses-permission`，依赖是 0，没有网络请求代码；运行层：刚才全程飞行模式，两局游戏、复盘、来源都正常；数据层：昵称和进度只存本机 SharedPreferences，退出不上传。**准确说法是『不申请权限、不联网、不收集个人信息』**，我们不夸大成『绝对安全』。」

**Q4：30 人前后测做了吗？教育效果怎么证明？**（C 答）

「方法已经定好：同一套 10 道单选题，玩之前测一次，复盘讲解后再测一次，5 分钟、匿名学号，统计平均分变化；KPI 是 30 人、正确率提升 ≥25 个百分点。**目前状态是【待实测】**，赛前完成施测，原始答卷和统计表留档，评委可以抽查。今天不报一个没有测过的提升数字。」

**Q5：AI 用了多少？怎么证明是学生自己做的？**（D 答；可开 git log）

「AI 我们用了，也愿意说边界。AI 做的是代码骨架初稿、文档整理、资料检索线索、台词润色；**不让 AI 做案例事实、来源、金额、日期、测试数据和评价**。每条来源由人点开原文核对，每个数字人审，代码编译通过、真机走通才进版本。证据是 31 次提交、4 个 Release、10 项缺陷修复和 123 张实机截图；评委可以任选一段代码或一个节点，学生现场解释。**AI 是效率工具，不是事实来源，也不是责任主体。**」

**Q6：为什么不做网页或微信小程序？**（A 答）

「目标场景是班会和机房：离线、零安装门槛、不收集数据。原生 Android 可以做到零权限、纯本地、安装包 2.55 MB、演示稳定；小程序和网页通常要服务器、域名、备案，校园网还可能有限制。原生还能用系统文件选择器、系统分享、桌面小组件这些能力，**不是网页套壳**。」

**Q7：案例版权和学生隐私怎么处理？**（A 答）

「案例只做话术改编，不大段搬运原文；人物匿名、平台名虚构，来源页逐条标注出处；界面不用真实平台商标或 Logo，不出现二维码和可操作网址。隐私上零权限、不联网、不收集任何个人信息；学生玩的数据只在本机。**这也是学校敢直接拿去用的原因。**」

**Q8：这个项目最难的技术点是什么？**（D 答；可开代码）

「最难的是在零第三方依赖下把体验做稳：翻书动效、逐条消息、损失滚动、超大字号适配、自建 ContentProvider 分享、桌面小组件，全部手写；还要让 17 本 JSON 剧本格式一致。我们用三样东西解决：校验脚本（17 本 0 错误）、运行日志（隐藏入口，可复制）、真机回归截图（123 张）。」

**Q9：把诈骗话术写这么细，会不会教坏学生？**（A 答）

「剧本只呈现骗子话术和止损点，不提供可操作的诈骗工具、账号、收款方式或真实链接；平台名虚构、人物匿名，来源页只放公开报道链接。课程设计是先玩、再看复盘、再讲评，重点在识别和处置；老师用前后测组织讨论。**我们把它定位为『安全地错一次』，不是教程。**」

**Q10：为什么剧本里是 34,400，真实案件写 50,400？**（A 答）

「34,400 是这一局里 5 笔代表性转账的累计：300 + 4700 + 1400 + 8000 + 20000；50,400 是剧本的参考损失，原文表述是『5 万余元』，**不是原文精确数字**。剧本没有把原文所有损失逐笔写进剧情，这一点我们在 PPT 和答辩里都标清楚。」

**Q11：如果学生每一步都选对，会怎样？**（A 答；先看冻结版实测）

「主线《低价全皮账号的诱惑》的安全线有 s1–s5 五个抵抗节点，走到『最后通牒』后会回到主线的换号/话费节点——这是模拟骗子不会一次就放弃；**如果冻结版实测仍没有给安全线做独立 0 元结局**，这是我们下一版第一项要补的。其它剧本里有 0 损失结局。今天现场演示的是『中途停手』路线，损失 6,400；**我们不把没做的说成做了**。」（若冻结版已补独立结局，按实际展示，并说明「全对路线」怎么走。）

**Q12：这个作品怎么推广？能落地吗？**（A 答）

「内容在 JSON 里，学校拿到 APK 就能用，不需要服务器；老师用 `docs/test-pre-post.md` 的前后测模板就能组织一节课；学生用剧本工坊把身边案例写成剧本，导出 `.json` 发给同学，导入就能玩。下一步 v3.0 班级共创、v3.1 教师端导出、v3.2 无障碍、v3.3 更多骗局；原则仍然是零后端、零权限、不采集个人信息。」

**被问住时的标准答法**（任何队员）

「这个我们还没有实测/还没做，材料里标的是【待实测】；我不能现场编一个数。会后我们把原始记录或代码给您看。现在能确认的是：……（说一个可核验的事实）。」
