# 《反诈剧本杀》PPT 大纲（15 页 · 8–10 分钟讲解版）

> 赛事：世界职业院校技能大赛 · 新一代信息技术赛道 · 中职组
> 用途：答辩讲解用 PPT；与 `docs/demo-script.md` 的时间轴对齐（PPT 讲 0–20 分钟，20–45 分钟现场演示，45–60 分钟数据与声明）。
> 数据标注：每页右下角写小字标注 **【已有数据】/【待实测】/【目标值】**；没测的数字一律写"待实测"，不画假柱状图。

## 一、总体规范

| 项目 | 要求 |
|---|---|
| 比例 / 时长 | 16:9；总讲解 8–10 分钟；每页 20–40 秒 |
| 主色 | 深蓝 `#1D3F6E`（与 App 主色一致），警示红 `#D93025` 只用于金额和风险，背景白/浅灰 |
| 字体 | 标题 ≥28pt、正文 ≥20pt、来源小字 ≥14pt；不用艺术字 |
| 文案 | 每页只留一句结论 + 少量关键词；长句放讲稿，不上屏 |
| 截图 | 全部来自冻结版 App，状态栏干净（无通知、无姓名、无手机号）；**不 P 图改数字**，与现场演示保持一致 |
| 合规 | 不出现警徽、公安 Logo、真实平台图标、收款二维码、可操作网址；不写"与公安合作""官方认证""公安推荐" |
| 来源 | 引用案例只用标题、发布方、日期、短句转述；不大段搬运新闻原文；URL 小字放页脚 |
| 底部 | 页码 + "数据口径：已有 / 待实测 / 目标" + "教学演示 · 非官方" |

## 四、时间分配与删页方案

| 版本 | 时长 | 讲哪些页 |
|---|---|---|
| 标准版 | 10 分钟 | 15 页全讲，每页 20–40 秒，演示段交给现场操作 |
| 压缩版 | 8 分钟 | 删第 8 页（流程可口头带过）、第 14 页合并到第 9 页，其余照讲 |
| 极简版 | 5 分钟 | 1、2、5、6、7、12、15 七页；其余用一句话串联 |

- 讲解节奏：开场痛点 2 分钟 → 作品与机制 3 分钟 → 技术 2 分钟 → 数据与声明 3 分钟。
- 第 12 页（测试与效果）**不能删**：它是"不编数据"的正面证明；但可以只讲口径，不放空白表。

## 六、内部备注（不上屏、不放进提交版 PPT）

1. 当前仓库有两个剧本：主线 `game-account.json` 为 21 节点、5 结局、2 条来源（校验 0 错误、最短通关 6 步），短剧本 `rebate.json` 为 12 节点、3 结局、5 条来源（校验通过）；主线与 README KPI（29 节点）还有差距。PPT 里凡"节点数 / 来源数"必须按冻结版实际数字写，说"来源数"时分清主线自身与全部剧本合计，不能直接抄 README 的 KPI 当结果。
2. `docs/sources.md` 目前只覆盖第二剧本（刷单返利），主线《游戏账号》的来源在 `game-account.json` 和 App 来源页；第 7 页截图/文案不要拿错清单。
3. 校验脚本当前 0 个错误（21 节点、5 结局）；冻结版复测 0 错误后才能把运行截图放上第 11 页。
4. 扩写后主线剧本已把"支付宝"改为"直接转 / 扫码"等虚拟表述；冻结前再全库搜一遍真实平台名、收款账号、二维码和网址，PPT 截图必须来自冻结版，不许 P 图。
5. 第 12 页不要做"提升 XX%"的柱状图（没有数据）；用空白模板和口径说明，反而显得可信。
6. AI 边界页（第 14 页）与 `demo-script.md` 第五节 Q5 口径必须一致：承认使用 AI，讲清人的核验与责任。
7. 案例截图/新闻图片如需引用，只放少量并注明出处；优先用自制时间线、示意图。
