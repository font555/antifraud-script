## 二、岗位职责与交接（逐人）

### 学生 A｜内容与来源核验（数字媒体艺术专业人员）

**一句话定位**：对"内容是不是真的、有没有出处"负总责，是整条链的第一个上游。

**主要职责**

1. **选题**：按公安部公布的高发电诈类型确定 6 类骗局，每类 2–3 本，共 17 本，覆盖游戏账号、刷单返利、冒充客服、冒充公检法、校园贷兼职、AI 换脸。
2. **来源**：只从公开报道取案例；每条登记标题、发布方、日期、URL、支撑哪些节点、改编说明；**没有来源的节点不写**，缺来源的标 `TODO`，交付前清零。
3. **改编**：人物匿名（王同学 / 某同学）、平台名虚构（"交易平台""某购物平台"）；金额取原文或在 `sources.note` 注明拆分；不搬运原文大段内容。
4. **格式**：按 JSON 协议写剧本，提交前跑 `tools/validate_script.py`，当前 17 本 / 405 节点 / 71 来源 / 0 错误 0 提醒；改剧本不动 Java。
5. **测评**：维护前后测 10 题、课后反馈 6 题和空白统计表；施测后汇总【待实测】。
6. **对外口径**：把来源卡和数据口径交给 D；答辩时能任抽一个节点说清它来自哪条来源、金额取原文还是拆分。

**交接与协同**

- **交付给 B**：剧本 JSON + `docs/sources.md` + 校验 0 错误的运行结果；B 收到后先跑一遍校验再接入。
- **接收自 C**：内容缺陷单（节点 id、截图、日志）；只改 JSON，不顺手改代码。
- **交付给 D**：71 条来源清单、3 条高频来源的纸质卡、冻结版数字口径（17 本 / 405 节点 / 71 来源）。
- **交付标准**：17 本 JSON 全部能解析；`next` 无断链；非结局节点 ≥2 个选项且至少 1 个高风险；每节点有来源或 `TODO` 已清零；校验 0 错误。

**对应证据**：`app/src/main/assets/scripts/` 17 个 JSON；`docs/sources.md` 71 条；`tools/validate_script.py` 输出；`docs/test-pre-post.md`、`docs/survey.md`；提交 `dd2e383`（补齐六类 17 本 405 节点 71 来源）。

**注意**：来源和金额是可以被评委当场抽检的地方，**不许用 AI 生成的事实、链接、日期**；拿不准的宁可不写，也不编。

### 学生 B｜程序实现（计算机程序设计员）

**一句话定位**：把剧本文本变成可安装、可演示的原生 Android 应用，对"跑不跑得起来"负总责。

**主要职责**

1. **架构**：model / engine / ui 分层；JSON 用 Android 自带 `org.json` 解析；不引第三方库、不引 Kotlin、不引 AndroidX。
2. **界面与交互**：书架翻书、逐条聊天、损失账本、复盘、来源、设置（字体 + 4 档字号）、剧本工坊、分享海报、桌面小组件、新手引导、隐藏运行日志。
3. **数据与状态**：`ScriptRepository`（读 assets 剧本）、`ScriptStore`（用户剧本导入导出）、`PathRecorder`（逐步记账）、`UserStore` / `SettingsStore`（本机存档）、`AppLog`（运行日志 + 崩溃兜底）。
4. **兼容与质量**：minSdk 24；大 / 小屏、四档字号、深色文字对比；编译通过才提交；按 C 的缺陷单逐条修。
5. **打包**：产出可安装 APK，版本号与 Release 一致；配合 C 复现问题、配合 D 提供功能清单和截图点位。

**交接与协同**

- **接收自 A**：剧本 JSON + 来源清单 + 校验结果；先跑校验、再接入。
- **交付给 C**：可安装 APK + 变更说明 + 已知问题；装不上、闪退、功能不符都算 B 的交接不完整。
- **接收自 C**：代码缺陷单（复现步骤、机型、`AppLog` 日志）；修完回给 C 回归。
- **交付给 D**：功能清单、截图点位（从哪个页面进、截什么）、版本号和"哪些功能已冻结"的说明。
- **交付标准**：`assembleDebug` 通过；干净安装能冷启动；8 条主路径能走通；零权限、零联网不被破坏。

**对应证据**：`app/src/main/java/` 32 个类 / 4,532 行；`app/src/main/res/` 39 个 XML / 1,128 行；`app/build.gradle` 的 `dependencies` 为空；`dist/antifraud-v2.3-debug.apk`；关键提交 `cbd47b5`（翻书动画）、`67a315b`（工坊 / 海报 / 小组件）、`29194e8`（缺陷修复）。

**注意**：不能为了赶进度偷偷加依赖或网络权限；"零依赖、零权限"是作品的命门，改一处要全组知道。

### 学生 C｜测试与打包（软件测试员）

**一句话定位**：对"敢不敢在评委面前现场演示"负总责，是内容和代码的验收人。

**主要职责**

1. **内容校验**：跑 `tools/validate_script.py` 并记录：17 本 / 405 节点 / 71 来源 / 0 错误 0 提醒；剧本一改就复跑，冻结版必须复测。
2. **功能回归**：按 8 条真机路径逐条走——冷启动 → 注册 → 书架；新手引导；单局完整通关；复盘 → 分享海报；剧本工坊新建 / 编辑 / 导出 / 导入；超大字号；桌面小组件；断网 / 飞行模式。记录崩溃次数，目标 0【待实测】。
3. **缺陷跟踪**：每条缺陷写清"机型 + 步骤 + 截图 + `AppLog` 日志"；跟踪到关闭并回归。已有记录：`29194e8` 修复新手引导卡死等 10 项问题。
4. **打包发布**：生成 APK、核对 2.55 MB、零权限、版本号；发布 4 个 Release（v2.0 / v2.1 / v2.2 / v2.3）；保留 `dist/` 历史包。
5. **演示保障**：演示机装冻结版、备用机同版本、电量 ≥80%、充好电、投屏线、勿扰模式、屏幕常亮；答辩前 30 分钟按检查清单过一遍。
6. **交接材料**：把冻结版 APK、版本号、测试通过项、未解决问题、截图清单交给 D。

**交接与协同**

- **接收自 B**：APK + 变更说明 + 已知问题；从干净安装开始测，不用开发机残留状态。
- **交付给 A**：内容缺陷单（哪个剧本、哪个节点、哪句话/金额不对）——A 只改 JSON。
- **交付给 B**：代码缺陷单（复现步骤、机型、日志）——B 修完由 C 复测。
- **交付给 D**：冻结版 APK + 版本号 + 已通过项 + 截图清单 + "哪些坑不能碰"的提醒。
- **交付标准**：冻结版只修崩溃、不再加功能；所有测试记录可追溯；Release 能下载安装；演示机能离线走完全流程。

**对应证据**：`dist/` 17 个历史 APK；GitHub Releases 4 个；`29194e8`（10 项缺陷 + 隐藏日志）；`logs/` 123 张开发截图；`tools/validate_script.py` 输出；测试表【待实测】。

**注意**：不能拿"目标值"当测试结果；不能把模拟器截图当不同机型的真机测试；测试记录要留空表也要留，答辩时如实说【待实测】。

### 学生 D｜材料与演示（广告设计师）

**一句话定位**：把作品变成评委看得懂、看得下去的材料和现场演示，对"讲不讲得清、演不演得稳"负总责。

**主要职责**

1. **材料**：15 页 PPT、6–8 分钟演示录屏、作品说明书、演示路线卡、纸质来源卡、冻结数字卡。
2. **视觉**：延续 App 的像素风；主色深蓝、警示红只用于金额和风险；截图统一比例、状态栏干净（无通知、无姓名、无手机号）；**不 P 图改数字**。
3. **数据口径**：PPT 每页右下角标【已有数据】/【待实测】/【目标值】；不画没有数据的柱状图；所有数字能指回 `docs/`。
4. **合规口径**：统一三行——教学演示 · 非官方；案例据公开报道改编；零权限 · 不联网 · 不收集个人信息。任何材料不出现警徽、公安 Logo、真实平台图标、收款二维码。
5. **演示编排**：主讲 1 人、操作 1 人、计时 1 人；准备兜底方案（录屏、备用机、纸质来源卡、演示卡）；答辩前完成至少 1 次完整彩排。
6. **交接闭环**：向 A 要来源卡和口径，向 C 要冻结版 APK 和截图清单，向 B 要功能清单；把彩排发现的问题回给 A/B/C。

**交接与协同**

- **接收自 C**：冻结版 APK + 版本号 + 测试通过项 + 截图清单；所有截图从冻结版重拍。
- **接收自 A**：3 条高频来源的纸质卡 + 71 条来源清单 + 数据口径。
- **交付给全员**：演示脚本、PPT 终稿、演示卡、兜底方案；答辩前 3 天发到群里，不再大改。
- **交付标准**：PPT 上每个数字都能被 `docs/` 验证；演示流程能在飞行模式下完整走一遍；现场任何一页被问住都能翻到证据。

**对应证据**：`docs/ppt-outline.md`；`docs/demo-script.md`；`artifacts/技术路线图.png`；`artifacts/share-poster-sample.png`；PPT / 视频 / 说明书成品【待核对：文件位置与版本】。

**注意**：不能自己"美化"一个没测过的数字；不能拿旧版本截图；不能临场改演示路线而不通知操作员和计时员。

## 三、交接链与协同规则（评委最关注）

```
公开报道 / 调研
      ↓  A 内容岗：选题、核来源、写剧本
  A：17 本剧本 JSON + sources.md（校验 0 错误）
      ↓  B 实现岗：接入、渲染、打包
  B：可安装 APK + 变更说明 + 已知问题
      ↓  C 测试岗：校验、真机回归、缺陷闭环、发布
  C：冻结版 APK + 测试通过项 + 截图清单
      ↓  D 材料岗：取截图、做 PPT / 视频 / 演示卡
  D：PPT + 录屏 + 演示卡 + 答辩
      ↓
  答辩：主讲（D）+ 操作（C 或 B）+ 计时（A）
      ↑ 反馈：C → A 内容缺陷；C → B 代码缺陷；D → A/B/C 口径与演示问题
```

| 3 | 实现 → 测试 | B → C | APK + 变更说明 + 已知问题 | 干净安装能开；功能清单齐全；版本号清楚 | D10 前 | 装不上 / 闪退退回 B |

### 三条协同规则

1. **只认文件，不认口头**：交接物是 JSON、APK、截图、日志、测试表；口头说"改好了"不算，文件到位才算。
2. **一个数字一个口径**：对外数字只认冻结表；A 改剧本导致数字变化时，必须同步 D，PPT 和讲稿一起改。
3. **冻结期只修崩溃**：答辩前 3 天冻结版本，不加功能、不改剧本、不换截图；只修崩溃和演示阻断问题。
